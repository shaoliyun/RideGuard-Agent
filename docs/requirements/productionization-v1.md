# TaxiAgent 场景升级与工程化需求文档

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 版本 | v1.0 |
| 状态 | 实施中 |
| 产品定位 | 面向城市复杂出行任务的可恢复、可审计 Agent 平台 |
| 首个差异化场景 | 异常出行与特殊人群护航 |

## 2. 背景与问题

项目已有多 Agent 路由、订单确认、工具调用、分层记忆、RAG 和工单能力，但仍存在生产化缺口：本地配置依赖秘密值、缺少一键启动环境、订单确认依赖松散 Redis 标记、工具缺少统一元数据、外部调用缺少一致的韧性策略、自动化测试和运行指标不足。

## 3. 目标与非目标

### 3.1 目标

1. 开源仓库不包含有效凭据，开发者可通过示例配置完成部署。
2. 基础依赖可通过 Compose 一键启动，应用可构建为容器镜像。
3. 下单流程具有显式状态、原子状态迁移和重复创建防护。
4. 暴露健康状态和业务指标，关键执行具有统一 request/trace 上下文。
5. 建立可扩展 Capability 接口和注册中心，新能力无需修改中央 switch。
6. 为后续“异常出行与特殊人群护航”场景保留风险、权限和确认元数据。

### 3.2 非目标

- 本版本不实现真实司机调度、支付和家属通知渠道。
- 不在本版本拆分微服务或引入重型工作流引擎。
- 不保证 MySQL 与 MongoDB 的分布式强一致；后续以 Outbox/补偿机制完善。
- 供应商后台凭据轮换由仓库维护者人工完成。

## 4. 用户与核心场景

### 4.1 用户

- 普通乘客：希望在天气、拥堵或大型活动影响下获得可靠方案。
- 特殊需求乘客：轮椅、孕妇、老人、携童、宠物或大件行李用户。
- 客服人员：处理自动流程无法完成的异常任务。
- 开发者：以插件式能力扩展地图、天气、车型和通知供应商。

### 4.2 目标链路

`需求识别 → 约束收集 → 多方案比较 → 风险说明 → 用户确认 → 创建任务 → 持续监控 → 异常重规划/人工接管`

## 5. 功能需求

### FR-01 安全配置

- 所有秘密通过环境变量注入。
- 提供无秘密的配置模板；缺少关键配置时快速失败并给出字段名。
- CI 应可接入秘密扫描。

### FR-02 本地与容器化运行

- 提供应用 Dockerfile 和基础设施 Compose。
- MySQL、Redis、MongoDB、Elasticsearch 均有健康检查和持久卷。
- 支持 `local`/`demo` 等 Profile 扩展，不改变生产默认值。

### FR-03 订单工作流

状态定义：`COLLECTING → QUOTED → WAITING_CONFIRMATION → CREATING → CREATED`；终止状态为 `CANCELLED/EXPIRED/FAILED`。

- 只允许白名单状态迁移。
- 状态迁移必须在 Redis 中原子执行。
- 同一会话的创建权只能被消费一次。
- 重复调用返回已创建订单，不产生第二个订单。

### FR-04 可观测性

- 提供 readiness/liveness/metrics 端点。
- 记录路由次数、工具调用结果、订单状态迁移及耗时。
- 日志携带 `requestId/userId/chatId`，不得记录凭据。

### FR-05 Capability 扩展模型

每项能力必须声明名称、风险级别、所需权限、是否需要确认和输入输出类型。注册中心负责唯一性校验与查询；业务 Agent 可逐步从硬编码工具列表迁移到注册中心。

### FR-06 外部依赖韧性

- 地图、天气和模型调用具有连接/读取超时。
- 只读调用允许有界重试；写操作默认禁止自动重试。
- 支持熔断、限流和明确降级，不允许模型猜测外部事实。

## 6. 非功能需求

| 维度 | 验收指标 |
| --- | --- |
| 安全 | Git 跟踪文件中无有效秘密；高风险能力必须确认 |
| 一致性 | 并发确认仅一次成功；重复创建不新增订单 |
| 可用性 | 外部服务失败可在配置超时内返回可解释错误 |
| 可观测性 | 健康端点和 Prometheus 指标可访问 |
| 可测试性 | 状态机、注册中心具有确定性单测 |
| 可扩展性 | 新增 Capability 无需修改 Registry 源码 |

## 7. 迭代与验收

### 第一阶段：安全可运行

- [ ] 将全部存量工具迁移为 Capability（渐进迁移，后续迭代）。

## 8. 风险与回滚

- 新状态机以兼容字段并行接入，不改变现有 HTTP 合约；异常时可通过配置回退旧流程。
- Redis 不可用时禁止创建订单，不以本地内存降级，避免重复副作用。
- Capability 抽象本期不强制迁移全部工具，减少一次性重构风险。
